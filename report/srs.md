## 1. Введение  

Документ описывает требования к десктопному приложению «Retro SFX Lab» — генератору ретро-звуков (прыжки, монеты, взрывы, лазеры) для инди-игр. Звук синтезируется из параметров (форма волны, огибающая, скольжение частоты, фильтры) и сохраняется в файл WAV. Он написан для Заказчика, разработчика, тестировщика и преподавателя. Бизнес-цели и границы продукта приведены в разделе 1.2, ограничения и пользователи в разделе 2, проверяемые требования в разделе 3.

### 1.1 Назначение документа

SRS определяет, **что** модуль должен делать, а не **как** он будет реализован. Заказчик использует его, чтобы подтвердить, что требования отражают его потребности. Разработчик берёт из него требования к проектированию и реализации, тестировщик строит по нему приёмочные тесты (раздел 4). Связанные артефакты: исходный код проекта, `README.md` и графические модели в каталоге `document/diagrams/`.

### 1.2 Область применения продукта

**Продукт:** «Retro SFX Lab», версия 0.1. Десктопное приложение для операционной системы Windows, состоящее из графического интерфейса на WPF и независимого ядра синтеза на C# (.NET 8).

**Назначение.** Разработчик игры выбирает готовый пресет (прыжок, монета, взрыв и т. д.) или создаёт звук с нуля, настраивает параметры ползунками, сразу слышит результат и экспортирует его в WAV для использования в игре. Приложение работает локально и не требует подключения к интернету.

**Бизнес-цели (источник: Заказчик):**

| ID | Бизнес-цель | Измеримый результат |
|----|-------------|---------------------|
| BO-1 | Разработчик быстро получает звук для прототипа игры | Звук из пресета создаётся и экспортируется не более чем за 3 действия |
| BO-2 | Звук можно тонко настроить без знаний цифровой обработки сигналов | Каждый параметр имеет понятное название, диапазон и мгновенно слышимый эффект |
| BO-3 | Результат пригоден для игровых движков | Файл WAV (16 бит, PCM) открывается в Unity, Godot и аудиоредакторах. Ядро на C# можно подключить к Unity/Godot напрямую. |
| BO-4 | Удачные звуки можно сохранить и воспроизвести повторно | Один и тот же набор параметров даёт одинаковый WAV-файл |
| BO-5 | Набор звуков проекта получается разнообразным | Кнопки случайной генерации и мутации создают вариации одного звука |

**Входит в область:** синтез звука по параметрам, пресеты, случайная генерация и мутация, воспроизведение (через NAudio), визуализация формы волны, история изменений, экспорт в WAV, сохранение и загрузка параметров в JSON.

**Не входит в область:** веб-версия приложения, версии для macOS и Linux, запись с микрофона, импорт и редактирование чужих аудиофайлов, многодорожечный секвенсор, музыкальная композиция, экспорт в MP3/OGG, облачное хранилище и учётные записи, мобильные приложения.

### 1.3 Определения, акронимы и сокращения

| Term | Definition |
|------|------------|
| 8-bit / чиптюн | Стиль звука игровых приставок 1980-х с простыми формами волны |
| ADSR | Attack, Decay, Sustain, Release — огибающая громкости: нарастание, спад, удержание, затухание |
| Bitcrush | Эффект уменьшения разрядности отсчётов, создающий «грязный» цифровой звук |
| Duty cycle (скважность) | Доля периода прямоугольной волны, в течение которой сигнал высокий |
| NAudio | Библиотека .NET для работы с аудио в Windows (воспроизведение, запись, обработка) |
| PCM | Pulse-Code Modulation — несжатое представление звука отсчётами |
| SRS | Software Requirements Specification — спецификация требований к ПО |
| Seed | Начальное число генератора случайных чисел; определяет воспроизводимость |
| Slide | Плавное изменение частоты звука во времени |
| SysML v2 | Systems Modeling Language версии 2 — язык моделирования для графической части |
| TBD | To Be Determined — значение ещё не согласовано с Заказчиком |
| UI | User Interface — пользовательский интерфейс |
| WAV | Контейнерный формат звукового файла (RIFF/WAVE) |
| WPF | Windows Presentation Foundation — фреймворк для создания десктопных интерфейсов в .NET |
| Арпеджио | Резкая смена высоты звука через равные интервалы времени |
| Вибрато | Периодическое колебание частоты звука |
| Пресет | Готовый набор параметров, соответствующий типовому игровому звуку |

## 2. Обзор продукта

### 2.1 Перспектива продукта

Приложение представляет собой единый исполняемый файл (`.exe`) для Windows, написанный на C# (.NET 8). Архитектурно оно разделено на независимое ядро синтеза (Class Library), графический интерфейс на WPF (Windows Presentation Foundation) и модуль воспроизведения на базе библиотеки NAudio. Использование C# позволяет использовать ядро синтеза напрямую в игровых движках (Unity, Godot). Владелец проекта — автор репозитория.

![Контекст системы](document/diagrams/01-context.png)

*Рисунок 1 — контекст системы (SysML v2: `document/diagrams/01-context.sysml`).*

### 2.2 Функции продукта

1. Синтез звука: формы волны, скважность, частота, огибающая ADSR, скольжение, вибрато, арпеджио.
2. Фильтры низких и высоких частот, эффекты bitcrush и снижения частоты дискретизации.
3. Пресеты, случайная генерация и мутация параметров.
4. Воспроизведение и визуализация формы волны.
5. История изменений параметров (Undo/Redo).
6. Экспорт в WAV, сохранение и загрузка параметров в JSON через системные диалоги Windows.

## 3. Требования

Каждое требование содержит поля: **ID**, **Statement**, **Rationale**, **Acceptance Criteria**, **Verification Method** (Test, Analysis, Inspection, Demonstration). Источник по умолчанию — Заказчик; ссылки вида C-N указывают на таблицу в разделе 2.6.

**REQ-INT-001 — Поддерживаемые операционные системы**
- **Statement:** Приложение должно запускаться и работать в операционных системах Windows 10 и Windows 11 (x64).
- **Rationale:** Заказчики используют разные версии Windows.
- **Acceptance Criteria:** Сценарии C-1…C-6 выполняются на Windows 10 и Windows 11 без ошибок в журнале событий.
- **Verification Method:** Demonstration

**REQ-INT-002 — Автономная работа**
- **Statement:** Приложение должно работать без подключения к сети интернет.
- **Rationale:** Работа в изолированной среде.
- **Acceptance Criteria:** При отключённом сетевом кабеле/Wi-Fi доступны все функции раздела 3.2.
- **Verification Method:** Test

**REQ-INT-003 — Отсутствие аудиоустройства**
- **Statement:** Если в системе нет устройства вывода звука (или драйвер недоступен), приложение должно сообщить об этом и сохранить доступными экспорт WAV и сохранение параметров.
- **Rationale:** Экспорт (C#) не зависит от воспроизведения.
- **Acceptance Criteria:** При отключённых динамиках кнопка Play неактивна (или выдает ошибку инициализации NAudio), экспорт работает.
- **Verification Method:** Test

**REQ-INT-004 — Управление с клавиатуры**
- **Statement:** Приложение должно поддерживать горячие клавиши: Пробел — воспроизвести, R — случайный звук, M — мутация, Ctrl+Z / Ctrl+Y — история, Ctrl+E — экспорт.
- **Rationale:** Быстрый подбор звука.
- **Acceptance Criteria:** Каждая клавиша вызывает действие; фокус ввода в текстовых полях не должен перехватывать глобальные хоткеи (кроме Ctrl+Z/Y).
- **Verification Method:** Test

**REQ-INT-005 — Размер окна**
- **Statement:** Окно приложения должно корректно отображаться при разрешении экрана от 1280×720 и выше.
- **Rationale:** Работа на ноутбуках и мониторах.
- **Acceptance Criteria:** Все элементы интерфейса доступны, при уменьшении окна появляются полосы прокрутки (ScrollViewer).
- **Verification Method:** Demonstration

#### 3.1.2 Аппаратные интерфейсы

**REQ-INT-006 — Устройство вывода звука**
- **Statement:** Приложение должно использовать звуковую карту Windows (по умолчанию) для воспроизведения синтезированного сигнала через API NAudio.
- **Rationale:** Пользователь должен слышать результат.
- **Acceptance Criteria:** При нажатии Play звук воспроизводится через активное устройство вывода Windows.
- **Verification Method:** Demonstration

#### 3.1.3 Программные интерфейсы

**REQ-INT-007 — Диалог сохранения WAV**
- **Statement:** При экспорте WAV приложение должно вызывать стандартный системный диалог Windows `SaveFileDialog` с фильтром `.wav` и предлагать имя файла согласно REQ-FUNC-018.
- **Rationale:** Стандартный механизм сохранения файлов в Windows.
- **Acceptance Criteria:** Открывается окно сохранения; при отмене файл не создаётся; при подтверждении — сохраняется по указанному пути.
- **Verification Method:** Test

**REQ-INT-008 — Диалог загрузки JSON**
- **Statement:** При загрузке параметров приложение должно вызывать `OpenFileDialog` с фильтром `.json`.
- **Rationale:** Загрузка сохраненных настроек.
- **Acceptance Criteria:** Открывается окно выбора файла; после выбора валидного JSON параметры применяются.
- **Verification Method:** Test

### 3.2 Функциональные требования

Цепочка синтеза звука (от параметров до готового массива отсчётов) проиллюстрирована на Рисунке 6.

*Рисунок 6 — цепочка синтеза звука (SysML v2: `document/diagrams/04-editor-flow.sysml`).*

**REQ-FUNC-001 — Формы волны**
- **Statement:** Система должна синтезировать звук с формой волны: прямоугольная, пилообразная, треугольная, синусоидальная, шум.
- **Rationale:** Базовые тембры чиптюна (C-2).
- **Acceptance Criteria:** Для каждой формы волны график и спектр соответствуют ожидаемой форме.
- **Verification Method:** Test

**REQ-FUNC-002 — Скважность**
- **Statement:** Система должна позволять задать скважность прямоугольной волны от 5 до 95 %.
- **Rationale:** Изменение тембра «ширины» импульса.
- **Acceptance Criteria:** При скважности 50 % доли высокого и низкого уровней равны; другие значения меняют долю.
- **Verification Method:** Test

**REQ-FUNC-003 — Базовая частота**
- **Statement:** Система должна позволять задать начальную частоту от 20 до 8000 Гц.
- **Rationale:** Высота звука.
- **Acceptance Criteria:** Измеренная частота первого периода равна заданной с погрешностью не более 1 %.
- **Verification Method:** Test

**REQ-FUNC-004 — Огибающая ADSR**
- **Statement:** Система должна применять огибающую громкости ADSR: attack, decay (по 0–2 с), уровень sustain (0–100 %), время удержания (0–2 с) и release (0–2 с); общая длительность не должна превышать 5 с.
- **Rationale:** Форма звука «удар», «писк», «взрыв».
- **Acceptance Criteria:** Амплитуда по времени соответствует заданной огибающей; сумма параметров > 5 с ограничивается.
- **Verification Method:** Test

**REQ-FUNC-005 — Скольжение частоты (Slide)**
- **Statement:** Система должна позволять задать скольжение частоты (−1…+1 октавы в секунду) и ускорение скольжения.
- **Rationale:** Прыжки, лазеры, падения.
- **Acceptance Criteria:** При положительном скольжении частота растёт, при отрицательном падает; значение 0 даёт постоянную частоту.
- **Verification Method:** Test

**REQ-FUNC-006 — Вибрато**
- **Statement:** Система должна позволять задать глубину (0–100 %) и частоту (0,1–20 Гц) вибрато.
- **Rationale:** Эффект «дрожащего» звука.
- **Acceptance Criteria:** При включении вибрато частота периодически отклоняется от базовой; при нулевой глубине вибрато нет.
- **Verification Method:** Test

**REQ-FUNC-007 — Арпеджио**
- **Statement:** Система должна позволять задать смещение частоты (−24…+24 полутона) и скорость смены.
- **Rationale:** Эффект монеты и бонуса.
- **Acceptance Criteria:** В момент смены частота изменяется скачком на заданное число полутонов.
- **Verification Method:** Test

**REQ-FUNC-008 — Фильтры**
- **Statement:** Система должна применять фильтры низких и высоких частот с частотой среза 20–20000 Гц.
- **Rationale:** Смягчение и «осветление» звука.
- **Acceptance Criteria:** При срезе 500 Гц ФНЧ ослабляет гармоники выше 500 Гц не менее чем на 12 дБ.
- **Verification Method:** Test

**REQ-FUNC-009 — Bitcrush и децимация**
- **Statement:** Система должна позволять снижать разрядность (1–16 бит) и частоту дискретизации эффекта (1000–44100 Гц).
- **Rationale:** Характерный «цифровой» звук.
- **Acceptance Criteria:** При 4 битах отсчёты принимают не более 16 уровней; при низкой частоте видны «ступеньки».
- **Verification Method:** Test

**REQ-FUNC-010 — Громкость**
- **Statement:** Система должна позволять задать общую громкость 0–100 % (по умолчанию 50 %).
- **Rationale:** Защита слуха и единый уровень.
- **Acceptance Criteria:** Пиковое значение отсчётов пропорционально выбранной громкости.
- **Verification Method:** Test

**REQ-FUNC-011 — Пресеты**
- **Statement:** Система должна содержать не менее 8 пресетов: прыжок, монета, взрыв, лазер, усиление, удар, блип, падение; выбор пресета заполняет все параметры.
- **Rationale:** Быстрый старт (BO-1).
- **Acceptance Criteria:** После выбора каждого пресета параметры соответствуют его описанию, звук воспроизводится.
- **Verification Method:** Test

**REQ-FUNC-012 — Вариации пресета**
- **Statement:** Система должна создавать вариацию пресета по seed: параметры отклоняются от базовых не более чем на ±15 %.
- **Rationale:** Разнообразие звуков одного типа.
- **Acceptance Criteria:** Разные seed дают разные звуки, один seed — одинаковый.
- **Verification Method:** Test

**REQ-FUNC-013 — Случайная генерация**
- **Statement:** Система должна создавать случайный набор параметров в допустимых диапазонах одной кнопкой.
- **Rationale:** Поиск неожиданных звуков (BO-5).
- **Acceptance Criteria:** Для 1000 запусков ни один параметр не выходит за диапазон.
- **Verification Method:** Test

**REQ-FUNC-014 — Мутация**
- **Statement:** Система должна изменять каждый параметр текущего звука на случайную величину не более ±10 % диапазона.
- **Rationale:** Тонкая вариация удачного звука.
- **Acceptance Criteria:** После мутации все параметры в допустимых диапазонах и отличаются от исходных.
- **Verification Method:** Test

**REQ-FUNC-015 — Воспроизведение**
- **Statement:** Система должна воспроизводить звук кнопкой «Play» и по клавише Пробел; повторное нажатие перезапускает звук. Воспроизведение реализуется через NAudio.
- **Rationale:** Быстрая проверка результата.
- **Acceptance Criteria:** Звук начинается не позднее чем через 100 мс; два нажатия подряд не создают наложения буферов NAudio.
- **Verification Method:** Test

**REQ-FUNC-016 — Визуализация**
- **Statement:** Система должна отображать форму волны всего звука на графике (элемент управления Canvas WPF) и обновлять её при изменении параметров.
- **Rationale:** Наглядность влияния параметров.
- **Acceptance Criteria:** После изменения любого параметра график обновляется.
- **Verification Method:** Test
- **More Information:** `document/diagrams/04-editor-flow.png`.

**REQ-FUNC-017 — Экспорт WAV**
- **Statement:** Система должна экспортировать звук в файл WAV (PCM, моно, 16 бит) с частотой 11025, 22050 или 44100 Гц на выбор.
- **Rationale:** Использование в игровых движках (BO-3).
- **Acceptance Criteria:** Файл открывается в стороннем аудиоредакторе, заголовок и длительность соответствуют параметрам.
- **Verification Method:** Test

**REQ-FUNC-018 — Имя файла**
- **Statement:** Система должна предлагать имя файла по названию пресета и номеру вариации; недопустимые символы заменяются подчёркиванием.
- **Rationale:** Удобство и совместимость с Windows.
- **Acceptance Criteria:** Для пресета «Прыжок/1» предлагается `Прыжок_1.wav`.
- **Verification Method:** Test

**REQ-FUNC-019 — Сохранение параметров**
- **Statement:** Система должна сохранять текущие параметры в файл JSON.
- **Rationale:** Повторное использование звуков (C-5).
- **Acceptance Criteria:** Файл создаётся по команде и содержит все параметры и версию схемы.
- **Verification Method:** Test

**REQ-FUNC-020 — Загрузка параметров**
- **Statement:** Система должна загружать параметры из JSON, проверяя структуру, версию и диапазоны значений; при ошибке текущие параметры не меняются.
- **Rationale:** Файлы могут быть повреждены.
- **Acceptance Criteria:** Корректный файл восстанавливает звук; для некорректного — выводится диалоговое окно с сообщением.
- **Verification Method:** Test

**REQ-FUNC-021 — Воспроизводимость**
- **Statement:** При одинаковых параметрах и seed система должна создавать побайтно идентичные файлы WAV.
- **Rationale:** Повторяемость результата (BO-4).
- **Acceptance Criteria:** Два экспорта подряд дают файлы с одинаковой контрольной суммой SHA-256.
- **Verification Method:** Test

**REQ-FUNC-022 — История**
- **Statement:** Система должна хранить до 20 последних состояний параметров и позволять возвращаться к ним (отмена и повтор).
- **Rationale:** Возврат к удачному варианту.
- **Acceptance Criteria:** Ctrl+Z возвращает предыдущее состояние, Ctrl+Y повторяет изменение.
- **Verification Method:** Test

**REQ-FUNC-023 — Защита от перегрузки**
- **Statement:** Система должна ограничивать пиковое значение звука до 0 dBFS без выхода за границы 16 бит.
- **Rationale:** Отсутствие искажений и щелчков при переполнении.
- **Acceptance Criteria:** В экспортированном файле нет значений, вышедших за диапазон; при максимальных параметрах нет переполнения.
- **Verification Method:** Test

### 3.3 Качество обслуживания

#### 3.3.1 Производительность

**REQ-PERF-001 — Скорость синтеза**
- **Statement:** Синтез звука длительностью 1 секунда на C# должен занимать не более 100 мс.
- **Rationale:** Мгновенный отклик при подборе параметров.
- **Acceptance Criteria:** Время расчёта для 1 с звука не превышает 100 мс на ПК среднего уровня.
- **Verification Method:** Test

**REQ-PERF-002 — Отклик интерфейса**
- **Statement:** После изменения параметра график должен обновляться не позднее чем через 100 мс.
- **Rationale:** Плавная работа с ползунками.
- **Acceptance Criteria:** Задержка между изменением ползунка и обновлением графика (UI thread) не превышает 100 мс.
- **Verification Method:** Test

**REQ-PERF-003 — Скорость экспорта**
- **Statement:** Экспорт звука длительностью 5 секунд в WAV должен выполняться не более чем за 500 мс.
- **Rationale:** Быстрое сохранение.
- **Acceptance Criteria:** Время от нажатия кнопки до появления окна сохранения и записи файла не превышает 500 мс.
- **Verification Method:** Test

#### 3.3.2 Безопасность

**REQ-SEC-001 — Отсутствие сетевой активности**
- **Statement:** Приложение не должно инициировать сетевые запросы или отправлять данные пользователя.
- **Rationale:** Параметры и звуки — собственность автора.
- **Acceptance Criteria:** Брандмауэр Windows не фиксирует исходящих подключений от исполняемого файла.
- **Verification Method:** Inspection

**REQ-SEC-002 — Проверка файла параметров**
- **Statement:** Система должна проверять загружаемый JSON: размер не более 64 КБ, типы и диапазоны значений, отсутствие неизвестных полей.
- **Rationale:** Защита от некорректных файлов.
- **Acceptance Criteria:** Файлы 100 КБ, со строкой вместо числа и с лишними полями отклоняются с сообщением.
- **Verification Method:** Test

#### 3.3.3 Надёжность

**REQ-REL-001 — Некорректные данные**
- **Statement:** Некорректные параметры и файлы не должны приводить к аварийному завершению приложения (Unhandled Exception).
- **Rationale:** Файлы приходят от разных источников.
- **Acceptance Criteria:** Для 10 негативных файлов выводится сообщение, приложение продолжает работу.
- **Verification Method:** Test

**REQ-REL-002 — Ошибка инициализации аудио**
- **Statement:** Если NAudio не может инициализировать устройство воспроизведения, система должна перехватить исключение и показать сообщение.
- **Rationale:** Конфликты драйверов или отсутствие звуковой карты.
- **Acceptance Criteria:** При ошибке кнопка Play блокируется, приложение не падает.
- **Verification Method:** Test

**REQ-REL-003 — Безопасная громкость**
- **Statement:** Громкость при запуске приложения и при загрузке пресета не должна превышать 50 %.
- **Rationale:** Защита слуха и динамиков.
- **Acceptance Criteria:** После загрузки приложения и пресета громкость не выше 50 %.
- **Verification Method:** Test

#### 3.3.4 Доступность

Отдельных требований нет: приложение является локальным десктопным ПО и не зависит от внешних серверов.

#### 3.3.5 Наблюдаемость

**REQ-OBS-001 — Журнал ошибок**
- **Statement:** Приложение должно записывать ошибки и предупреждения в текстовый файл в папке `%LocalAppData%\RetroSfxLab\logs` с кодом, уровнем и описанием.
- **Rationale:** Диагностика проблем.
- **Acceptance Criteria:** Для ошибок REQ-FUNC-020 и REQ-REL-002 в лог-файле есть записи с кодом и стеком вызовов.
- **Verification Method:** Inspection

### 3.4 Соответствие стандартам

**REQ-COMP-001 — Формат WAV**
- **Statement:** Файл WAV должен соответствовать спецификации RIFF/WAVE (PCM, формат 1) с корректными полями размеров.
- **Rationale:** Совместимость с движками.
- **Acceptance Criteria:** Файл успешно проверяется утилитой анализа и читается в трёх сторонних программах.
- **Verification Method:** Test

**REQ-COMP-002 — Доступность интерфейса**
- **Statement:** Контраст текста и фона элементов управления должен быть не менее 4.5:1 (WCAG 2.1, критерий 1.4.3), ползунки доступны с клавиатуры (стрелки).
- **Rationale:** Читаемость и доступность.
- **Acceptance Criteria:** Проверка инструментом аудита (Windows Accessibility Insights) не выявляет нарушений.
- **Verification Method:** Inspection

**REQ-COMP-003 — Формат параметров**
- **Statement:** Файл параметров должен быть корректным JSON (RFC 8259, UTF-8) с полем `schemaVersion`.
- **Rationale:** Совместимость и расширяемость.
- **Acceptance Criteria:** Файл разбирается стандартным парсером (System.Text.Json); поле версии присутствует.
- **Verification Method:** Test
