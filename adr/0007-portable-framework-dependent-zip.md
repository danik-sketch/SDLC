# Формат поставки: переносимый ZIP, framework-dependent

## Контекст и постановка задачи

Нужно выбрать, как пользователь получает программу. SRS 2.5 допускает, что на ПК пользователя установлен .NET Runtime, а программа работает автономно без интернета. Вопрос: self-contained, framework-dependent, установщик?

## Драйверы решения

* Простота получения и запуска, отсутствие установки
* Малый размер поставки
* Допущение SRS 2.5: Runtime установлен
* Минимум работы для сборки в рамках 3 недель

## Рассмотренные варианты

* Переносимый ZIP, framework-dependent, `win-x64`
* Переносимый ZIP, self-contained
* Установщик MSIX / MSI

## Итог решения

Выбранный вариант: «Переносимый ZIP, framework-dependent, `win-x64`», потому что он минимален по размеру и работе и соответствует допущениям SRS. Если окажется, что у заказчика нет Runtime, добавляется второй артефакт self-contained без изменения кода.

### Последствия

* Хорошо, потому что публикация одной командой `dotnet publish`
* Хорошо, потому что при удалении программы файлы пользователя в `%AppData%` не затрагиваются
* Плохо, потому что при отсутствии Runtime приложение выдаёт системное предложение установить его

### Подтверждение

Запуск архива на чистой Windows 10 и Windows 11 с установленным Runtime (`tests/build.md`); проверка размера архива и состава файлов.

## Плюсы и минусы вариантов

### Переносимый ZIP, framework-dependent, `win-x64`

* Хорошо, потому что размер поставки в единицы мегабайт, достаточно распаковать и запустить
* Хорошо, потому что соответствует допущению SRS 2.5
* Плохо, потому что нужен установленный .NET Desktop Runtime

### Переносимый ZIP, self-contained

* Хорошо, потому что запускается без Runtime
* Плохо, потому что размер порядка 70–150 МБ при размере самого приложения в несколько МБ

### Установщик MSIX / MSI

* Хорошо, потому что привычен пользователю Windows
* Плохо, потому что требует сертификата или дополнительной работы, не нужен для учебной версии

## Дополнительная информация
