# Архитектура: библиотека Core без UI и приложение на MVVM

## Контекст и постановка задачи

SRS 2.1 требует, чтобы ядро синтеза не зависело от интерфейса, а SRS 1.2 и BG-3 предполагают использование результата в Unity и Godot. Вопрос: как разделить код, чтобы DSP-логика тестировалась без окон и звукового устройства и могла быть переиспользована?

## Драйверы решения

* Тестируемость синтеза без WPF и NAudio (SYS-NFR-009)
* Возможность переиспользовать ядро в игровых движках
* Простота: два разработчика, три недели
* Чёткая граница ответственности между интерфейсом и логикой

## Рассмотренные варианты

* Два проекта: RetroSfx.Core и RetroSfx.App, MVVM, DI
* Один проект WPF
* Плагинная архитектура (эффекты как плагины)

## Итог решения

Выбранный вариант: «Два проекта: RetroSfx.Core и RetroSfx.App, MVVM, DI», потому что только он даёт тестируемое переиспользуемое ядро при минимальной сложности.

### Последствия

* Хорошо, потому что 100 % логики синтеза проверяется модульными тестами
* Хорошо, потому что работа делится на независимые задачи (важно для плана с junior-разработчиком)
* Плохо, потому что нужно следить за направлением зависимостей (только App → Core)

### Подтверждение

Архитектурный тест (xUnit): сборка `RetroSfx.Core` не содержит ссылок на `PresentationFramework` и `NAudio`; проверка выполняется в `dotnet test` (SYS-NFR-009).

## Плюсы и минусы вариантов

### Два проекта: RetroSfx.Core и RetroSfx.App, MVVM, DI

* Хорошо, потому что Core не имеет ссылок на WPF и NAudio и тестируется xUnit
* Хорошо, потому что junior-разработчик получает изолированные задачи по контрактам
* Нейтрально, потому что требуется описать интерфейсы (`IAudioPlayer` и другие)
* Плохо, потому что немного больше начального кода, чем в одном проекте

### Один проект WPF

* Хорошо, потому что минимум структуры
* Плохо, потому что DSP-код смешивается с интерфейсом, тесты требуют WPF
* Плохо, потому что ядро нельзя использовать в Unity и Godot

### Плагинная архитектура (эффекты как плагины)

* Хорошо, потому что расширяемость
* Плохо, потому что избыточна для версии 1.0 и увеличивает срок и стоимость

## Дополнительная информация

Связанные представления SDD: 002-composition, 011-patterns, 013-dependency. Связанные ADR: ADR-0004.
