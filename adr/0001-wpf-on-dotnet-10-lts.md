# UI-платформа: WPF на текущей LTS-версии .NET (10)

## Контекст и постановка задачи

Retro SFX Lab — десктопное приложение для Windows 10/11 (SRS 2.3, REQ-CON-010). Нужен UI-фреймворк с готовыми элементами (ползунки, диалоги) и возможностью рисовать график формы волны. Версия .NET в SRS 0.2 указана как 8, но поддержка .NET 8 закончилась 10.11.2026. Вопрос: какой UI-фреймворк и какую версию .NET выбрать, чтобы уложиться в срок и не начинать проект на платформе без обновлений безопасности?

## Драйверы решения

* Требование SRS: C#, WPF, Windows 10/11 (REQ-CON-010)
* Срок выпуска 07.12.2026 и ограниченный бюджет: нужен знакомый разработчику стек
* Собственная отрисовка графика формы волны (SYS-FUNC-011)
* Долгосрочная поддержка платформы (LTS): .NET 10 поддерживается до ноября 2028 года

## Рассмотренные варианты

* WPF на .NET 10 (LTS)
* WPF на .NET 8 (LTS, как в SRS 0.2)
* WinForms на .NET 10
* WinUI 3 / Windows App SDK

## Итог решения

Выбранный вариант: «WPF на .NET 10 (LTS)», потому что он соответствует требованиям SRS к стеку (C#, WPF, Windows), поддерживается до 2028 года и не требует новых зависимостей. Формулировка REQ-CON-010 и SRS 2.3 обновлена с .NET 8 на .NET 10 (SRS 0.3).

### Последствия

* Хорошо, потому что интерфейс и MVVM реализуются штатными средствами платформы
* Хорошо, потому что проект стартует на поддерживаемой версии платформы
* Плохо, потому что пользователю нужен .NET 10 Desktop Runtime (допущение SRS 2.5 уточнено)
* Плохо, потому что приложение не запустится на macOS и Linux (принято в SRS 1.2)

### Подтверждение

Проекты имеют `TargetFramework` `net10.0` (Core) и `net10.0-windows` с `UseWPF = true` (App). Сборка и запуск на чистых Windows 10 и 11 проверяются тестом `tests/build.md` (REQ-CON-010).

## Плюсы и минусы вариантов

### WPF на .NET 10 (LTS)

* Хорошо, потому что соответствует SRS (C#, WPF, Windows) и находится на поддержке
* Хорошо, потому что богатая привязка данных для MVVM и свой элемент графика через `DrawingContext`
* Хорошо, потому что работает на Windows 10 и 11
* Плохо, потому что только Windows (кроссплатформенность вне области проекта)

### WPF на .NET 8 (LTS, как в SRS 0.2)

* Хорошо, потому что совпадает с формулировкой SRS 0.2
* Плохо, потому что поддержка завершилась 10.11.2026, обновления безопасности больше не выходят

### WinForms на .NET 10

* Хорошо, потому что простой в освоении
* Плохо, потому что слабая привязка данных, неудобный MVVM
* Плохо, потому что устаревший внешний вид элементов

### WinUI 3 / Windows App SDK

* Хорошо, потому что современный интерфейс
* Плохо, потому что сложнее сборка и поставка, нет опыта у команды
* Плохо, потому что противоречит требованию SRS о WPF

## Дополнительная информация

Связанные решения: ADR-0002 (разделение на Core и App), ADR-0007 (поставка). Связанные требования: REQ-CON-010, SYS-NFR-008.
